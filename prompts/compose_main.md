## 本次任务：写月报的总览部分

下面用户消息中是本月的重点材料：各分类重要的结论卡、扫读中价值高的话题、@我 的事项、私聊中对方最后发言而我没有回复的会话，以及基本统计。材料中的 `m数字` 是消息编号。

只输出一个 JSON 对象，每个字段的值是一段 Markdown（不要写章节标题，代码会加）：

```json
{
  "overview": "一页速览：一屏能读完。先写本月最重要的几件事，最后一句写需要你处理的事共几项",
  "actions": "需要你处理：用 `- [ ]` 列表，每项写清楚做什么、为什么、期限，最重要的加 ★",
  "key_events": "本月要事：跨分类、按事情组织的几件要事。每件用 `### 标题` 开头（重要的写成 `### ★ 标题`），先一句结论，再 1–3 行经过，最后写这件事里真正参与的人",
  "insights": "本月洞察：每条写观察、依据、可能的含义或建议、置信度。站得住的才写"
}
```

- 每条内容后面用 `[m123]` 标出处，只用材料中出现过的编号。
- 按事情组织，不按群罗列。只有同一件事才合成一条：同一个项目、同一笔钱、同一次约定，经手的人也对得上。主题相近（都是商务、都是 AI 工具、都是健康），或者只是有一两个共同的人、在同一个群里，都不算同一件事：分开写，不重要的就不进本月要事。一条要事的标题和结论要能对应到一件具体的事，不要写成"商务""资金"这类把几件事装进一个筐的标题。
- 每条材料带有代码按发送人算出的 `我参与`。`我没发言` 表示这些消息里没有你说的话：不要写成你说了、报了价、答应了什么。如果它是别人之间的商量、询价、合作，就是别人的事，不要写成你的机会或待办，"涉及的人"里不写"你"，只有对你确实有影响时才写，并写清是谁和谁；如果它是发给群里所有人、或者提到你的通知，可以写成需要你知道或处理的事。
- @我 的事会由代码单独列表，这里只在它确实重要时写进"需要你处理"或"本月要事"。
